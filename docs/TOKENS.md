# 迷宫代币规划与统计

点击游戏右侧的“迷宫助手”，再进入“代币规划”。里面依次是代币使用预算、使用计划与商店目录、代币获得统计；不占用原生迷宫页面，切换右侧原生或其他助手页签可返回对应内容。

## 使用规划

参考公会建设的目标、排序和累计预算方式，支持 14 种迷宫商店升级及客户端提供的代币兑换商品。设置目标等级或兑换次数后加入规划，可以调整顺序、修改目标和移除项目。

- 预算留空时跟随背包代币余额，也可手动填写；保留金额不参与当前可用预算。
- 升级花费逐级累加。游戏等级提升后，方案按新等级计算剩余费用；目标已达到时显示“已完成”。
- 商品按兑换次数乘每次价格计算，并显示每次产出。无法可靠判断兑换是否用于某个本地计划，所以兑换完成后需手动移除计划。
- 各行按顺序共用同一预算，显示本项花费、累计花费、相对当前可用预算的缺口及预计还需挑战次数。
- “单次收入”留空时使用已确认结束且无冲突记录的平均收入；也可填写自己的估计。“再打”用于计算预计可用预算，不改变实际收入统计。
- 没有可用均值、余额或当前等级时显示横线或“待核对”，不把未知当作零。没有完整收入记录时仍可手动填写单次估计。

例如生活行动速度从 0 升至 3 级，需要 40 + 80 + 120 = 240 代币。若预算 500，随后加入 800 代币的冷却升级，累计需要 1,040，当前还差 540；按单次收入 250 估算还需 3 次。

只保存本地方案，购买和兑换仍由玩家在游戏商店完成。

## 获得统计

按角色和挑战开始时间保存每次迷宫的实际累计掉落。展示逐次收入、已记录累计收入、挑战次数及完整记录的平均收入。

数据来自页面已有 `characterLabyrinth.lootedItemsData` 的 `/items/labyrinth_token`，以及被动接收的 `labyrinth_updated` 消息。余额来自背包物品；消费不会冲减收入，也不会把余额增长直接算作收入。

同一挑战反复读取、刷新和重复消息只更新已有记录，采用最大已知累计值。当前挑战显示“本次已获”。只有明确收到 `isActive: false` 才计为已结束；切换到下一次挑战、退出页面或缺少挑战数据，不推断前次已完整结束。若结束值与较高的已知累计值冲突，保留已知数据并标为“数据待核对”，不纳入完整均值。

累计收入包含已读取到的当前及中断挑战；平均收入只采用已确认结束且无冲突的记录，完整零收入场次也参与。未读取的历史挑战不会补猜，这不是账号终生收入。

## 保存与数据来源

数据库为 `mwi-labyrinth:tokens:v1`，对象仓库 `characters`，格式版本 `schema: 1`。按浏览器网站来源和角色 ID 隔离，保存方案和独立收入记录，不读取原有逐层挑战档案，不上传游戏数据。

写入使用同一 IndexedDB 事务读取并合并，避免多个页面重复累计或覆盖其他挑战。保存失败会保留当前页面的修改并提供重试；提示消失前不要关闭页面。读取失败或格式损坏时不会用空方案覆盖原数据。“导出记录”可下载当前角色的方案和收入 JSON；暂不提供导入与清空收入记录功能。

升级上限、花费和等级换算按 2026-11-10 检查的本地游戏客户端 `getUpgradeMaxLevel`、`getUpgradeCost`、`getUpgradeLevelFromCharacterInfo` 实现；兑换商品和价格读取当前页面 `initClientData.labyrinthShopItemDetailMap`。游戏若调整升级规则，需要同步更新 `src/tokens/model.js`。缺少明确等级字段时不推测零级。

## 验证

`test/tokens.test.js` 检查成本、排序预算、未知值、实际收入去重及完整均值。`tools/browser-tokens.mjs` 使用离线游戏结构与真实浏览器 IndexedDB，检查页签挂载/切换/重建/销毁、键盘操作、窄屏、导出、刷新恢复、并发写入和保存失败重试。

这些用例不访问游戏服务器、不触发购买或挑战，不能代替真实游戏验收。

## 0.12.0：按公会建设组织工作区

页签内采用连续布局：预算与完成进度在上，使用计划和商店目录在中间，收入统计在下方。宽屏并排显示计划与目录，窄屏纵向排列，计划操作可换行。

| 公会建设中的功能           | 迷宫代币规划中的对应功能                                                          |
| -------------------------- | --------------------------------------------------------------------------------- |
| 建筑目录、分类和搜索       | 基础、生活、战斗、兑换目录；显示当前等级、下一级费用或每次兑换价格与产出          |
| 点击加入、再次定位已有计划 | 点击目录加入下一级或一次兑换；重复点击只展开和定位已有项目                        |
| 目标等级、+1、+5           | 升级选择目标等级；兑换填写次数；两类均支持 +1/+5，上限处停止                      |
| 分组施工队列、费用展开     | 每个项目一组，可展开每级费用及全队列累计费用；大量兑换按次数汇总，避免生成数万行  |
| 可完成升级数、预算截止     | 按顺序计算可完成到哪一级/第几次兑换，并显示下一步还差多少；未知前项不会被当作免费 |
| 拖动、上下按钮、键盘排序   | 支持拖动手柄、上下按钮；聚焦手柄后可用 Alt+上/下调整                              |
| 清空与撤销                 | “更多”中清空计划，8 秒内可撤销；不清空收入记录，之后的计划编辑会结束撤销机会      |
| 复制计划、导出 CSV         | 复制可读计划、导出含逐级费用的计划 CSV；另可导出实际收入 CSV 和完整 JSON 记录     |
| 规划周数与预计完成时间     | 规划挑战次数与预计还需挑战次数，不假设玩家的挑战频率和完成日期                    |
| 固定预测起始周             | 固定预测起始挑战，后续新挑战自动纳入；只采用范围内已确认结束且无冲突的记录均值    |
| 目录和明细展开状态保存     | 保存目录开关、搜索、分类、费用明细与收入历史展开状态，按角色隔离                  |

“预算可完成”使用本次规划预算，即当前预算加上所选挑战次数的预测收入，再扣除保留代币，最低为零。当前余额不足以覆盖保留金额时，未来收入先补足这部分。“完成计划预计还需”按计划花费加保留代币、减去当前预算后的缺口计算，包含尚未补足的保留金额，不重复扣除规划中的未来收入。

“完整记录平均收入”始终统计全部有效完整记录；“预测单次收入”可以按起始挑战筛选或手动填写。更改预测参数不改写实际收入。没有对应数据的公会试炼、周结算、建筑特有状态不搬入迷宫；历史记录仍以实际读取为准，不新增虚构历史或自动修改实际收入的功能。

旧版 `schema: 1` 方案与收入可直接读取；新界面偏好与 `forecastStart` 为可选字段。没有新字段时使用默认值，下一次编辑正常保存，不删除旧数据。
