# 迷宫代币规划

取消独立“代币规划”页签和侧栏页面，改为直接挂载在游戏原生“迷宫商店”页中：每个可规划商品卡片上添加紧凑加减小按钮，商店底部吸底显示一行预算摘要和已选清单（不推动上方卡片位置）。

## 卡片控件与预算

- 未加入计划的商品仅显示一个 `+` 小按钮；点击后原位向左展开 `−`、数量输入和 `+`，`+` 位置保持不变以便连续点击。
- 升级项显示计划增加的级数，费用按当前等级逐级累加，底部清单显示起止等级与费用；游戏实际升级后自动同步剩余级数和费用，已满级商品不注入按钮。
- 兑换项显示计划兑换次数，按次数乘单价计算；单次产出大于 1 时在底部清单同时标出总数量。
- 卡片小按钮完全阻止事件冒泡，不触发原生购买弹窗；点击卡片其他区域仍正常走游戏原有购买流程。
- 底部吸底一行仅显示 `预算`（留空跟随当前背包代币，显式 `0` 生效）、`合计`、`剩余`（超出预算显示红色负数，未知余额或费用显示 `—`），以及有计划时的 `清空` / 8 秒 `撤销`。
- 已选清单直接展示于摘要下方，点击名称可滚动定位对应商品卡片，点击 `×` 移除单条。

只保存本地方案，购买和兑换仍由玩家在游戏商店完成。

## 保存与兼容

数据库为 `mwi-labyrinth:tokens:v1`，对象仓库 `characters`，格式版本 `schema: 1`，按网站来源及角色 ID 隔离。旧方案中的保留代币、挑战次数、单次收入和预测起点不再参与计算，原存储记录与后台被动收入记录继续兼容保留。保存失败保留修改并在摘要行末尾提供重试；读取失败不会用空方案覆盖原数据。

升级上限、花费和等级换算按 2026-11-10 检查的本地游戏客户端 `getUpgradeMaxLevel`、`getUpgradeCost`、`getUpgradeLevelFromCharacterInfo` 实现；兑换商品和价格读取当前页面 `initClientData.labyrinthShopItemDetailMap`。缺少明确等级字段时不推测零级。

## 验证

`test/tokens.test.js` 检查成本、预算、未知值、旧数据兼容及原生商店卡片识别。`tools/browser-tokens.mjs` 使用离线游戏原生商店结构与真实浏览器 IndexedDB，在 1440px / 390px / 320px 下覆盖原卡片加减与直接输入、事件隔离、连点不漂移、满级/未知/非代币处理、预算空值/零值/超支负数、实际升级同步、定位高亮、清空撤销、保存失败重试、商店切离重挂、稳态零重绘及销毁清理。

这些用例不访问游戏服务器、不触发购买或挑战，不能代替真实游戏验收。
