# 架构说明

当前不引入运行时 npm 依赖。构建按 `tools/runtime-sources.mjs` 的显式顺序拼接源码；没有构建时间戳，同样的输入生成相同字节。
`package.json` 是版本来源，锁文件与其保持一致。脚本名为“迷宫助手”，包名为 `milky-way-idle-labyrinth-assistant`，全局实例为 `__mwiLabyrinthAssistant`。

路径规划使用 `src/core.js`、`src/runtime/map-reader.js` 和 `src/ui/planner-view.js`。每秒读取当前可见地图，数据或节点改变时才计算和绘制；隐藏页面暂停读取。`core.js` 的 `planningOrigins` 统一筛选连通已通关区、有序队列及相邻白房，供主路、道具破局和宝箱支线使用；`map-reader.js` 保留原生队列顺序，不读取隐藏房间。

房间计算在 `src/calculator/` 中按功能拆分：配置与文案、游戏数据适配、生活概率、战斗引擎和角色适配、实时进度、推荐等级、悬浮详情、日志、胜率分布、外部模拟器桥接与生命周期。各模块注册初始化函数，共用单个实例的 `ctx`；源码可单独解析和静态检查，不通过动态代码生成拼接模块。`simulation-cache.js` 管理有容量上限的本地战斗样本数据库；`combat-engine.js` 按完整输入指纹复用并校验样本，展示快照仍由原有结果模块管理。`restart.js` 为独立纯计算，不依赖页面或存储。`integration.js` 负责与本项目的状态失效、侧栏中的计算区域和重开提示衔接。

`src/vendor/compression.js` 是内置压缩库。`src/userscript.js` 最后执行，统一启动及销毁路径规划和房间计算。房间计算读取 React 状态和 `initClientData`，被动拦截已有进度消息；不会发起游戏请求。销毁时清理 Worker、待处理 Promise、定时器、监听器、自有节点；只有原型 getter 仍是本实例安装的版本时才恢复它，不覆盖后来安装的第三方钩子。

路径规划与胜率估算保持独立：估算结果不会改变红白房间的路线判断，也不会替用户修改游戏队列。外部模拟器入口遵循用户 2026-11-08 的明确授权，详见房间计算说明。

新增存储时使用独立前缀，并按服务器和角色隔离；未知、空值和零值需要区分。读取失败不能伪造等级或库存。只复用已确认的数据来源，不引入第二条竞争性的 WebSocket 拦截路径。

`references/`、`.workbench/` 和旧插件都不属于构建输入。正式产物不包含本机服务地址；开发加载器单独申请本机读取权限。

`ui/sidebar.js` 识别右侧原生页签栏，提供路线与计算、房间推荐和代币规划三个内容槽；前两个在同一页上下排列，代币规划单独一页，并管理页签选择、其他助手激活通知及销毁恢复。`planner-view.js` 通过 `calculationHost(grid)` 提供计算区挂载位置；`userscript.js` 将这个接口传给计算实例。控制区在侧栏内正常排版，日志和分布详情窗仍按需打开。

`experience-policy.js` 提供无 DOM 的经验效率公式与非单调等级区间扫描；`experience.js` 负责角色隔离的经验目标、界面及与原推荐流程的衔接。普通房间预览和批量扫描使用同一公式，扫描只计算必要统计量。

推荐预填由 `src/ui/recommendation-prefill.js` 处理点击编辑及一次性草稿写入，`src/calculator/prefill.js` 适配三种推荐值、开关存储及生命周期，不保存游戏设置。

`ui/theme.js` 提供所有自有窗口的共享样式，限定命名空间，不修改原生游戏操作。`calculator/presentation.js` 负责房间推荐平铺布局、主窗口设置折叠和预览信息层次；保留原计算事件与状态控制，销毁后不再访问 DOM。

`calculator/archive-model.js` 是独立的字段筛选、事件合并和压缩模型；`archive-store.js` 按层写入 IndexedDB，通过同一事务合并挑战元数据和压缩记录；`archive.js` 负责角色识别、采集和生命周期。接收消息复用 `live-progress.js` 的现有钩子，发送方向仅增加白名单命令的被动观察，不改变消息。页面隐藏时仍保留后台采集；销毁时停止采集、恢复自有钩子并尝试提交待写队列。该档案不依赖旧房间日志，不向计算和推荐提供输入。

代币功能由 `tokens/model.js` 提供成本、预算和收入合并的纯计算，`tokens/store.js` 用独立 IndexedDB 原子保存角色方案与收入；`calculator/tokens.js` 读取现有游戏状态、复用接收消息钩子并管理保存重试。`ui/token-workspace.js` 负责公会建设式预算、分组队列、目录、统计和本地交互，`ui/token-view.js` 将工作区挂到共享侧栏的代币槽中，不修改 React 状态、不触发商店操作。详见 `TOKENS.md`。

## 当前布局（2026-11-11 撤回页签迁移）

默认恢复原位置：路线与计算在地图旁，房间推荐在原生自动化页，代币规划在迷宫商店旁。右侧布局实现保留，`src/ui/sidebar.js` 的 `enabled` 默认是 `false`；改为 `true` 后重建即可切回。`tools/browser-layout-restore.mjs` 检查默认布局，`tools/browser-sidebar.mjs` 显式开启右侧布局进行回归。此说明替代前文的默认右侧布局描述。

0.12.5：档案保持原数据库与键，压缩值改为兼容读取旧格式的事件分块，合并过程只处理尾部数据；单事务合并相邻同层队列，提交后才移除。房间结果以所属角色快照合批保存，底层存储接口可显式指定角色供延迟提交使用。经验设置保存失败保留各角色草稿并支持读回校验与重试。代币视图提供可见性与打开通知，目录缓存按角色、升级、商店数据和原生标签变化更新；计算面板监听过滤迷宫外变动，隐藏且空闲时不执行完整刷新。
