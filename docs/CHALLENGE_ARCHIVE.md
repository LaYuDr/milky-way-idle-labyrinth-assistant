# 迷宫挑战档案

0.6.0 起，插件运行期间自动记录客户端提供的迷宫地图与操作。当前只采集和保存，不参与路线规划、胜率、经验推荐或重开判断，不提供分析界面，也不上传。

## 记录范围

- 按当前站点、角色 ID、迷宫 `startedAt` 分隔挑战，再按 `currentFloor` 分层。刷新和重新进入页面后使用同一档案；角色或开始时间改变则使用另一份。
- 每层保存地图尺寸及全部格子位置。已知房间保存类型、生活技能或怪物、推荐等级、进入次数、失败次数及通关状态。未揭示的数据留空，后续揭示补齐；不会推算隐藏等级。
- 保存收到更新的时间、递增序号、路径队列变化、进入/失败计数变化、通关变化、火把/迷雾/信标剩余数量变化及生活/强化行动进度。
- 被动记录客户端已发出的排队/取消排队、开始探索、停止迷宫行动、下层、离开迷宫、使用信标或迷雾请求。保存字段采用白名单，不保存其他请求、聊天、凭据或完整角色状态；不修改或主动发送任何游戏请求。
- 发出请求记录为 `command_sent`，并不表示服务器已执行。通关仅依据服务器房间状态变化；不能据此断言请求来自手动点击还是游戏自动化。

初次观察一层时，已有的通关状态作为基线保存，不编造此前的操作历史。一次更新出现多个通关房间时，它们属于同一批，`orderKnown: false`，不假设坐标顺序就是通关顺序。只有单个变化可定位在相邻观察之间；时间是客户端观察时间，不是服务器精确完成时间。离线或关闭插件期间无法记录过程，只能在回来后保存收到的最新状态。

首次发出“进入迷宫”请求时尚无挑战标识，档案从服务器返回有效地图开始；因此不保留这次初始请求本身。缺少角色标识、挑战开始时间或有效地图时不生成猜测档案。只收到页面空状态不会推断通关或退出；服务器明确移除迷宫数据时记录 `run_removed`，不推断离开原因。

## 存储与压缩

浏览器 IndexedDB 数据库：`mwi-labyrinth:challenge-archive:v1`。

| 对象仓库 | 键                           | 内容                                                                            |
| -------- | ---------------------------- | ------------------------------------------------------------------------------- |
| `runs`   | `[角色 ID, startedAt]`       | 格式版本、首次/最后观察时间、全挑战递增序号、已记录楼层、服务器移除时间（如有） |
| `floors` | `[角色 ID, startedAt, 楼层]` | 该层基线、已知房间、路径、资源、事件及去重状态的压缩包                          |

IndexedDB 随游戏域名隔离，不在国际服、国服或测试服之间合并。没有固定保留条数，不自动删除旧挑战；也不受“房间日志”的清空按钮和条数上限影响。

0.12.5 起，每层使用 `lz-string-chunks` 外层格式：每 128 条事件封存为一块，`head` 保存最新地图、去重状态和不足 128 条的尾部事件，`chunks` 保存历史块。写入时校验历史块的压缩字节与块顺序，只解压、合并和重压尾部；完整读取仍检查各块并还原全部事件。旧版整层压缩包在下一次成功写入时转换，事务失败不会留下半份新格式。旧版插件不能读取新格式，回退代码前应保留站点数据库备份，不清理档案。

复用随插件内置的 MIT 许可 `lz-string 1.5.0`，采用 `compressToUTF16` / `decompressFromUTF16`。每层压缩包包含 `codec`、版本、原始字符数和 FNV-1a 完整性校验。校验用于识别意外损坏，不是加密或防篡改签名。实际压缩率取决于内容，不承诺固定比例。

每批最多合并 64 条相邻且同角色、同挑战、同楼层的记录，不跨边界重排。一次事务读取最新挑战元数据和该层档案，按接收顺序合并后同时写回。只在事务提交完成后移除待写队列；多连接写入不使用内存里的旧副本覆盖数据库。重复地图、重复进度及同一个消息对象的重复读取不会新增相同事件。进入/失败计数和通关状态不因旧快照回退；已知字段不因空格子或缺失字段而被擦除。

每次观察到变化就排队写入，不等待关页才保存。写入失败时保留内存队列、定时重试，并在主窗口中显示未保存提示。已有档案不会被删除；损坏的压缩包会拒绝覆盖。浏览器被强制关闭时尚未提交的队列仍可能丢失；清理站点数据会删除该站点的档案。当前未添加导出、同步、自动清理或容量管理功能。

## 实现与验证

- `src/calculator/archive-model.js`：字段筛选、快照合并、事件、压缩与校验。
- `src/calculator/archive-store.js`：数据库、原子写入、待写队列与恢复。
- `src/calculator/archive.js`：页面状态、迷宫消息和操作请求的被动记录与生命周期。
- `test/archive.test.js`：已知/未知数据、历史基线、事件顺序、去重、跨层、压缩与损坏检查。
- `tools/browser-archive.mjs`：真实 IndexedDB 的离线浏览器矩阵，覆盖消息钩子、白名单、刷新、并发连接、配额失败恢复、角色/挑战/楼层隔离及清理。

消息中存在顶层或迷宫对象内的 `characterId` 时，所有已提供身份都必须匹配当前角色；更新、删除和进度消息采用同一检查。没有角色字段的旧协议仍沿用当前页面状态，不能据此识别所有无标识的延迟消息。

消息字段来自本地留存的游戏客户端源码 `.workbench/game-main.js` 中的 `handleLabyrinthUpdated`、`handleLabyrinthRoomProgress` 及相应发送方法。客户端协议变化时需重新核对；夹具矩阵不能替代真实游戏验收。

事务实现参考 [MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB) 和 [事务 complete 事件](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event)：在同一读写事务中读取并更新，提交完成后再确认保存。
