# 路径规划

## 已采用的规则

方形网格，上下左右相邻。入口左上，出口右下。先从入口沿已通关房间找出连通区域，再按原生队列顺序纳入能接到该区域的非红房，并扩展它连接的已通关区域。没有有效待完成队列时，主路线可从这片区域及其直接相邻、已揭示且白色的挑战房起步。有有效待完成队列时，只从接通区域续接，不再把其他未入队白房当成免费起点。孤立白房、孤立通关岛、断开的队列都不能直接作为免费起点。

沿用起点之后的新格计数：合法起点本身不计成本，合法队列视为玩家准备完成的前段；这不是从入口开始的总消耗，也不是保证队列中的未知房间一定可通行。没有有效待完成队列时，未入队的白房只向外取一层，不能沿一串未通关白房免费延伸。有待完成队列后，经过其他未入队、未进入的白房正常计一格；已进入房间仍按既有规则不重复计新格。未领取、未进入且未规划的宝箱不是免费起点。已进入房间不重复计新格，但进入或失败不等于通关，不据此扩展起点区域。红房不能通过。宝箱支线与主路线分开计算，不自动操作游戏。

优先级依次为：主路线新格成本最少；主路线与一次相邻收获可能触及的探索范围最大；主路线直接新增揭示最多。范围按“通过连通检查的原生队列＋候选剩余路线”统一去重，并扣除已经揭示的格子。已选前段尚未实际揭示的覆盖范围仍参与比较，不能只评估新起点以后的半条路线。孤立、变红或顺序不合法的队列项不参与评分；未知队列房间仍是未知房，不把预计覆盖写成实际揭示。

第二层是几何机会指标，不是假设每个房间都能拿到宝箱。对路径旁尚未知类型的房间、已知未领取宝箱，计算进入它后可能再揭示的相邻格。已知不能通过、已通关、已知非宝箱房不作为候选收获支线。这里“一次”表示向主路外多走一格的深度；机会范围是所有候选支线可触及格子的并集，不代表进入一个宝箱就能揭示全部范围，不计算无限宝箱连锁，也不推测宝箱概率。

图片中的 8×8 上图路线直接可见36格，机会范围51格；下图直接可见38格，机会范围48格。第一版必须优先上图这类有外扩空间的路线，不能仅为了多看两格挤到边缘。不是所有地图都固定走第三列，障碍、已探索区域和地图尺寸都会改变路线。

## 算法

将通过连通检查的起点同时设为距离零的起点，用多起点 0–1 最短路计算新格成本，并将相连零成本格折叠为一组，避免免费往返导致搜索循环。在满足最短成本的路径图中保留不同揭示集合，比较机会范围和直接揭示范围。先用多个内侧折线路径建立候选，避免大地图把搜索额度全用在贴边路线的变体上；随后默认最多访问20,000个搜索状态；未搜完时仍返回最低新格成本路线，路线区悬停提示说明同成本探索收益未穷尽。小地图用独立穷举交叉验证。初始候选、深度搜索与最终评分使用同一份队列覆盖并集；旧路线候选也必须通过当前连通、相邻和最低成本检查，不能绕过障碍或增加新格成本。

已知宝箱单独在“已揭示且确认能通过”的图上寻路，使用与主路相同的合法起点，其中未知的队列起点不能用于这张已知图。宝箱已经在主路线或通过连接校验的队列中时，不再重复推荐支线。没有绕过未知或未确认挑战房的保证时不显示为可达。每条支线成本独立，不把多个支线成本相加当成最优收集计划；成本同样只计算合法起点之后的新格，不表示相对主路的额外消耗。领取后地图变化会重新比较主路线。地图上的“宝”只标宝箱目标，途经普通房用金色线和圆点，不把普通房标为宝箱。

## 起点、重算与原生队列

0.10.2 修正此前允许远处白房独立起步的规则。`planningOrigins` 统一筛选主路、道具路线和宝箱支线的起点：

1. 从入口沿 `visited`（已通关）扩展；`entered` 仅影响新格计费，不用于这一步连接。
2. 按原生队列顺序检查房间。只有非红房且已在当前区域内、或与区域四邻相接的房间才能接入；接入后可扩展相连的已通关岛。
3. 不合法的队列项跳过，其后依赖它才能连接的房间不能起步；后面的独立分支若能接到已有区域，仍可接入。后选的连接房间不会追溯修复前面已经断开的项。
4. 只有合法队列中没有未通关房间时，才加入当前区域直接相邻的已知白色挑战房作为候选；存在合法待完成房间时，这些未入队白房须作为后续路径正常计费。无效、孤立队列不改变起点规则，全部已通关的队列也不会占用初始起步机会。普通宝箱不作为额外白房候选。

所有合法候选共同比较，不锁死旧路线。地图事实、楼层和道具条件未变，且原生队列只沿当前建议追加时，把旧路线的合法剩余段先作为候选；只在同成本、同道具成功率、同探索收益时优先保留它。更短或收益更好的路线出现后正常更新。删除、重排、改选队列，新增揭示、红白状态变化、换层、离开地图和读取失败时不沿用旧路线偏好。该偏好只在当前页面保存，重新加载后按当前完整队列计算。终点只有通过上述连接检查后，才能作为零成本续接点并返回仅含终点的路径；孤立终点即使出现队列或已进入标记，也不能跳过前段。

队列只读原生 `queueNumber` 中的安全正整数，按编号排序；重复编号存在歧义时忽略这些项。增删、改选、顺序变化会触发重算；仅统一调整数字但相对顺序不变时不重算。助手不修改玩家队列。队列中的未知房间仍保持未揭示状态，变红、取消或前段断开后立即重新检查连接。

## 页面读取

当前依据官方前端 `main.8add56c3.chunk.js` 的房间渲染契约读取 `data-room-x/y`、clearedRoom、roomLevel、roomLevelWarning、roomEntered、roomFailCount、queueNumber 和可见图标。源码查询来源为 `https://www.milkywayidlecn.com/`，2026-11-07 核对。只读取可见房间 DOM，不再读取 React 状态。`visibleRoom` 也会标记队列扩展后的可选格，因此不能作为已揭示依据；只有实际等级、图标或通关状态用于判断。

挑战房等级带 `LabyrinthPanel_roomLevelWarning` 时为红色，作为障碍；有等级且无警告时为白色，按能通过规划；没有等级的未知房仍保留未知状态。已通关房保持可通行。游戏的警告来自 `wouldRoomBeSkipped`，依据有效等级和当前跳过阈值，不是保证战斗成功的胜率。助手按用户要求沿用红白规则，不改游戏设置，不再提供手动覆盖。

路径规划与房间计算共用一个固定窗口，挂在 body，按地图实际坐标放在左侧；不改原生地图节点、容器样式、大小、位置和滚动方式。常态显示自动路线开关、快速通过层数和本层显示按钮，不显示剩余格数、下一格、已揭示数量或“虚线待探索”。存在宝箱、道具建议、无路或错误时仍显示相应信息。统一按钮控制两个区域的展开和收起；窄屏默认收起，左侧空间不足时放到窗口左下角。滚动时保持在视口内，离开地图后隐藏，销毁时移除事件监听。

## 路线显示范围

“快速通过至第几层”保存一个不包含该层的上限：设置 6 时，仅第 1—5 层自动显示，第 6 层起隐藏；1 表示所有层默认隐藏，留空表示所有层自动显示。保存在当前站点浏览器的 `mwi-labyrinth:route-stop-before-floor:v1`，不修改游戏自动化设置。仅接受大于等于 1 的安全整数；无效输入不覆盖原设置，保存失败时本次仍生效并显示提示。

“自动显示路线”控制按范围自动显示；“显示本层路线 / 隐藏本层路线”可单独覆盖当前层，即使自动显示关闭也可手动开启。更改范围或自动开关时清除临时覆盖；换层、开始新挑战、切换角色和重新加载脚本后也清除，同层新增房间或改选队列不会清除。只是显示范围，寻路规则及房间计算不变。

层数取现有游戏状态 `characterLabyrinth.currentFloor`，同时核对房间数组与可见地图尺寸；用角色、本次挑战的 `startedAt` 和层数组合识别当前层。读取失败且设置了层数范围时默认隐藏，可通过按钮手动显示；未设置范围时维持所有层显示。已规划房间、道具和探照灯仍按各自规则处理。

## 验证范围

本地覆盖图片两条路线、最短成本、免费回头、障碍、封闭入口、宝箱支线、机会去重、有限搜索及30组小地图独立穷举；另用120张含已进入房、孤立通关岛、红房和有序队列的混合地图，以独立的逐边松弛算法核对最少道具和新格成本。浏览器测试台覆盖红白等级变化、入口封闭、宝箱、免费往返、15×15地图和窄屏。早期真实游戏仅验证6×6页面读取与展示，未点击房间或操作游戏队列。0.10.2 新规则已用用户8×8截图复现，并通过桌面和窄屏离线浏览器矩阵；尚未在真实游戏独立验收。

路线编号仅基于推荐路径：起点、已进入或已通关的房间不占编号，同一新格重复经过也只计一次；其余新格从 1 按首次经过顺序连续编号。主路线与宝箱支线重叠时保留主路线数字，其他位置的原生队列编号不计入。

## 道具破局（0.7.0）

只有从所有候选起点都找不到不用道具的终点路线时，才启用破局规划。破局使用同一套通过连通检查的起点；队列中的红房及其断开的后段不能作免费起点，不能通过选中红房或孤立白房免除道具成本。

破局路线先最少突破房间，再最少新格；成本相同时优先各次道具都成功的概率，再比较外扩机会和直接揭示。以 `格子总数 + 1` 作为每个障碍的权重，保证一次道具成本始终大于一条简单路线全部新格成本。零成本连通区只合并无需道具的已进入房间；已进入但仍堵塞的房间仍消耗道具。搜索上限仍为 20,000 状态，最少道具及最少新格有保证，成功率和探索收益的同成本比较可能被截断。

`src/runtime/shrouds.js` 只读取现有角色状态中的 `shroudItemHrid`、`shroudCount` 与地图尺寸，房间等级仍取可见 DOM，绝不读取隐藏等级。读取不到库存时不假设有道具；未知道具不猜适用等级。客户端本地源码 `.workbench/game-readable.js` 的 `getShroudSuccessRate` 及 `isValidShroudTarget` 显示：基础/高级/专家迷雾对应等级 50/100/999，超出后每级降低 2 个百分点，降为 0 的房间不能作为使用目标；道具可清除可见挑战房，但不获取经验和奖励。上述为当前本地客户端快照规则，后续客户端更新需要复核。

“至少 X 次”指每个指定房间第一次使用都成功时所需次数，非保证消耗；成功率低于 100% 时提示可能失败，失败或数量变化后重算。道具不足时仍绘制明确标注的参考路线，不称为可执行主路。未知房间仍按可能通行估计，不能保证隐藏地图不再出现障碍。底部橙色“道”标记仅作建议，不点击游戏按钮、不修改队列、不提交使用道具请求。

## 探照灯最佳位置

`src/runtime/beacons.js` 按本地游戏客户端（2026-11-08）`getBeaconPattern` / `getBeaconRevealRooms` 的规则计算：基础为十字 5 格，进阶为 3×3 的 9 格，专家为曼哈顿距离不超过 2 的 13 格。枚举地图上的所有中心，包括已揭示中心；裁切边界，排除入口、出口、已揭示和已通关房间。每个格子只统计一次。返回最高新增数量及全部并列中心，零收益时不标记。单盏分析供联合规划使用，不预测奖励价值。

只从页面现有状态读取探照灯标识、数量和地图尺寸；内容仍使用可见 DOM，不读取隐藏房间。未知类型不猜测范围，零库存默认停止标记，手动解除库存限制后可继续假设规划，未知库存明确提示余量未识别。道具类型或数量变化可更新推荐而不重算路径。新增揭示、DOM 重建和楼层变化后重新统计。

### 一至三盏联合规划

探照灯菜单直接展示，不使用准备开关或折叠。规划数量默认不超过已识别的库存，也支持手动解除本层库存限制；未知库存暂停推荐。显示合计新揭示数，以及每盏的推荐坐标和按顺序去重后的新增数。相同收益优先少用道具。

纯计算 `plan` 搜索全部不同覆盖集合，使用安全的数量上界剪枝，不截断候选。最大化多盏覆盖并集；已揭示、入口和出口不重复计数。按地图、楼层和灯型缓存结果，不因鼠标移动重新搜索。实际使用后按新地图重新规划，不自动使用道具。

地图只显示方案的 ①②③，小标记优先放底部空位，避让原生等级、图标、胜率和路线，无空位则省略标记，坐标仍在面板。默认以浅色透明区块显示联合方案的新增并集，悬停或键盘聚焦表格行突出该盏按顺序去重后的新增范围；移开恢复全部范围，原生使用预览期间由游戏展示范围，所有地图标记不拦截鼠标。原生预览数量与本地计算不一致时暂停推荐。没有使用历史、候选对比或迷你地图。

## 地图大小

侧栏“地图大小”只调整迷宫网格的 CSS zoom（50%—200%），格子中的路线、等级、胜率及探照灯标记同步缩放，周边面板不缩放。点击百分比恢复 100%。设置保存于本地 `mwi-labyrinth:map-zoom:v1`；存储不可用时本次页面仍可调整。换图重新应用，退出地图或销毁助手时恢复网格原有内联 zoom。此设置不修改房间坐标或寻路输入。

探照灯色块预览：直接以 `data-mwi-lab-beacon-fill` 为目标格子着蓝灰底色（#486b7d），不添加覆盖原生内容的色层，不修改游戏内联样式。清理时移除专属属性，恢复游戏自身背景。游戏原生道具预览开启时撤去助手色块。

数量输入默认支持 0 至实际库存（最多为地图格数），0 清除全部助手探照灯标记；未知库存禁用数量输入和加号。到库存上限后，加号保持可用：第一次点击加号变色，第二次点击解除限制并增加一盏；无需快速双击，焦点离开加号或库存变化会取消待确认状态。解锁后输入框与加号均可超出库存，数量框边框与超库存数字变色，不新增可见提示文字或按钮；手动将数量减到或输入到库存以内时恢复限制。解锁仅在本层、本类型有效，换层、换类型、库存变为未知或离开地图时复位；普通地图刷新及已知库存变化保留解锁。零库存也可按相同步骤进行假设规划。解锁后最多输入地图格数，不更改游戏库存或执行购买。1—3 盏仍精确搜索，更多盏以贪心并集为初始方案，最多检查 20000 个搜索分支；预算用完时使用快速联合方案，不保证全局最优；菜单仅显示揭示格数，不展示算法名称。候选集合数限定内部搜索深度，无收益点不重复消耗道具。编号使用普通数字的小号蓝灰圆形标记，继续避让原生内容。

原生探照灯使用预览期间，菜单独立显示悬停坐标和 `beaconPreviewCount`（可见预览的新增格数），不使用联合规划并集代替。0 盏规划不关闭原生预览计数；无悬停位置时显示移动提示，退出原生预览后隐藏，不残留旧计数。

菜单参数保存在本机：地图缩放和速通层数沿用原存储；自动路线与本层覆盖保存于 `mwi-labyrinth:route-display:v1`，本层覆盖只在角色、挑战开始时间及层数相同的情况下恢复。探照灯规划数量保存于 `mwi-labyrinth:beacon-quantity:v1`，零也有效；库存不足时仅限制本次显示数量，不覆盖用户保存值，库存恢复后可恢复原数量。已解锁的超库存规划只在同层、同道具类型恢复，不保存待确认点击；未知库存仍禁止增加。场数沿用按角色保存的计算器设置，胜率分布开关使用 `mwi-labyrinth:calculator:distribution-enabled:v1`，同样按角色隔离。恢复分布开关不主动触发手动计算。库存、揭示结果与日志窗口打开状态不作为参数保存。损坏数据回退默认值，存储不可用时本次仍可操作。
